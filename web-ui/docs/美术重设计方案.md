## 1. 现状评估

总评：**体系已接近成熟**。令牌单一事实源、EP 双主题变量对接、图表主题化、三态收敛、可访问性全局规则均已落地且有防线。以下为逐条核对结果，⚠️/❌ 即本方案的增量来源。

### 1.1 强项（✅，不重复做）

- ✅ **EP primary 九档 var() 化**：`element-overrides.css:4-10` 全引 brand 令牌，dark 同手法 `dark.css:117-123`，符合 `element-plus-design-color` 的主色档位模型，消灭了 EP 默认蓝双轨。
- ✅ **功能色四族全档映射**：`element-overrides.css:14-48` / `dark.css:126-160`，base/light-3/5=图形级、light-7/8/9=浅底级、dark-2=文本级、error=danger 单轨——比 EP 官方默认映射更完整（官方只给值，本项目给了三级语义分层）。
- ✅ **dark 模式手法规范**：`dark.css:9` 首行 `@import` EP dark css-vars + 其后 `html.dark` 覆写，与 `element-plus-dark-mode` 的 "Customizing Dark Mode" 官方路径逐字一致；`color-scheme` 声明（`base.css:5-13`）符合该 skill 的 Quick Start 要求。
- ✅ **中性色 dark 全量对接**：`dark.css:163-190` 把 bg/fill/text/border/mask/shadow 全族映到 dark 令牌，对照 `element-plus-design-color` 中性色表无缺档。
- ✅ **字号阶梯对齐 EP 六阶**：`tokens.css:139-149` 的 12/13/14/16/18/20 与 `element-plus-design-typography` 的 extra-small→extra-large 一一对应，自增 22/24 两档（页标题/监控读数）有登记。
- ✅ **数字排版**：`.num` + `tabular-nums`（`utilities.css:39-41`）、监控读数 `var(--fs-metric)`（`SensorsView.vue:397-401`）。
- ✅ **图表主题化**：`chartTheme.ts:72-117` tooltip/图例/网格/刻度/字体全走计算色，tension 0.3 全局曲线化（`chartTheme.ts:100`），开关量由组件显式豁免——机制干净。
- ✅ **三态与错误可达性**：`StateBlock.vue:2-8` loading 骨架 > error 警示+重试 > empty 引导 > 内容，契合 ui-ux-pro-max ux 域 Loading Indicators（骨架）/ Error Recovery（重试路径）；`el-alert` 原生 `role=alert`，满足该域 Error Messages（"use aria-live or role=alert"）。

- ✅ **移动弹层收敛**：`element-overrides.css:137-152` dialog/drawer/message-box/picker 全收口，footer 防压缩。
- ✅ **PWA 门面**：`index.html:5` viewport-fit=cover、`index.html:8-9` theme-color 双 meta media + 防闪烁脚本三处职责；safe-area 令牌化（`tokens.css:219-220`）。

| 组合 | 实测 | 判定 |
|---|---|---|
| light text-1/2/3 on surface | 15.40 / 9.38 / 5.18 | ✅ |
| light text-3 on bg / surface-2 / fill-light | 4.70 / 4.82 / 4.69 | ✅（贴线通过，注意勿再调浅） |
| 主按钮白字 on brand-600（light/dark） | 5.21 / 5.07 | ✅ |
| light nav 激活胶囊 brand-700 on brand-050 | 6.60 | ✅（与 S2 注释一致） |
| 功能色 text on soft（light 四族） | 4.86–6.20 | ✅ |
| dark text-1/2/3 on surface | 13.79 / 9.24 / 5.29 | ✅ |
| dark 功能色 text on soft | 7.00–8.88 | ✅ |
| **dark `::selection`（brand-700 on brand-100）** | **1.66** | ❌ |
| 焦点环 brand-500 on white（非文本 3:1） | 3.92 | ✅ |

### 1.3 盲点（⚠️/❌ → 增量来源）

- ❌ **A. dark 文本选区对比度 1.66:1**：`base.css:55-58` 的 `::selection` 用 `var(--brand-100)` 底 + `var(--brand-700)` 字；light 下 5.89:1 合格，但 dark 覆写后 brand-100=#173c4a、brand-700=#1d5f78（`dark.css:35,41`），选区文字几乎不可读。S5/S6 抽测未覆盖 selection 场景。
- ⚠️ **B. light 侧 EP 中性色映射不全、与 dark 不对称**：`element-overrides.css` 只设了 border 四档、text 三档、`--el-fill-color-light`、`--el-bg-color-page`；未设 `--el-bg-color` / `--el-bg-color-overlay` / `--el-fill-color(-dark/-darker/-extra-light)` / `--el-text-color-placeholder` / `--el-text-color-disabled`，这些在 light 回落 EP 默认（#a8abb2、#c0c4cc 等），而 dark 全部显式映射（`dark.css:163-190`）。后果：placeholder/disabled 两主题色族不一致；`element-overrides.css:58` 的 `#f0f4f9` 还是游离字面量（不在令牌表，介于 surface-2/surface-3 之间）。依据：`element-plus-design-color` 中性色表列出的可主题化变量全集。
- ⚠️ **C. 图表系列仅靠色相区分**：`SensorTrendChart.vue` 无 `borderDash`/点形冗余编码（grep `borderDash|dash|pointStyle` 零命中，系列区分全靠 `chartPalette()` 8 色）；且 chart-1 #1a86a2 与 chart-6 #0d5a70 色相接近。违反 ui-ux-pro-max `charts.csv` Trend Over Time 与 Multi-Variable Comparison 两条的 Accessibility Notes："Use solid, dashed, and dotted line styles plus direct series labels; **never distinguish series by hue alone**"。色觉障碍用户（约 8% 男性）在多系列趋势图上受影响。
- ⚠️ **D. 触摸目标 40px 低于平台惯例**：`tokens.css:221` `--touch-target: 40px`。过 WCAG 2.5.8 AA（24px），但低于 ui-ux-pro-max ux 域 Touch Target Size 的平台指引（iOS 44pt / Android 48dp）。移动精简端用户戴手套/现场操作的场景下 44px 更稳。
- ⚠️ **E. dark brand 阶梯语义未注释**：`dark.css:39-40` brand-400 与 brand-500 同值 #3398b8，800/900 反转为浅色档（dark 语境"越大越浅"）——是有意设计但文件内无说明，后续维护者易误"修正"。登记即可，零风险。

## 2. 可行增量方向

### 2.1 【采纳】V-A：dark `::selection` 对比度修复（对应盲点 A）

- 现状：`base.css:55-58` 单套 selection 变量，dark 继承后 1.66:1。
- 建议：`dark.css` 增加 `html.dark ::selection` 覆写——底 `var(--brand-200)`（#1d4a5a）、字 `var(--text-1)`（#e8eef4），实测对比度 8.24:1；顺手把盲点 E 的 dark brand 阶梯反转语义在 `dark.css` 品牌阶梯块头加两行注释登记。
- 依据：WCAG 1.4.3（正文 4.5:1）；element-plus-dark-mode 的覆写路径（html.dark 下追加自有规则，`dark.css` 已有同手法先例 `dark.css:196-199`）。
- 改动量：**小**（dark.css 一处新增规则 + 注释）。收益：消除唯一 ❌ 级对比度缺陷。

### 2.2 【采纳】V-B：light 侧 EP 中性色补全（对应盲点 B）

- 现状：light 只映射了中性色子集，placeholder/disabled/fill 族回落 EP 默认灰蓝，与 dark 全量映射不对称；`element-overrides.css:58` 有游离字面量 `#f0f4f9`。
- 建议：`element-overrides.css` 补齐 `--el-bg-color: var(--surface)`、`--el-bg-color-overlay: var(--surface)`、`--el-fill-color: var(--surface-3)`、`--el-fill-color-lighter/-extra-light: var(--surface-2)`、`--el-fill-color-dark/-darker: var(--surface-3)`、`--el-fill-color-blank: var(--surface)`、`--el-text-color-placeholder: var(--text-3)`、`--el-text-color-disabled: var(--text-3)`（与 `dark.css:163-177` 逐条对称）；`#f0f4f9` 收敛为 `var(--surface-2)`（#f4f7fb，色差极小）或按老规矩登记新令牌。注意 placeholder/disabled 改映射后颜色由 #a8abb2 加深为 text-3（5.18:1），视觉上略深，需抽验表单页。
- 依据：`element-plus-design-color` Neutral Colors 表（这些变量本就是官方可主题化项）；令牌唯一事实源约束。
- 改动量：**中**（一个文件 +8~10 行 var() 映射；风险面在 fill 族被 EP 内部多处引用，需抽 5 页走查：表单/表格/弹层/下拉/分页）。收益：双主题中性色同族对称、消灭游离字面量、placeholder/disabled 对比度 2.30/1.75 → 5.18。

### 2.3 【采纳】V-C：图表系列非色相冗余编码（对应盲点 C）

- 现状：多系列折线仅靠 8 色循环区分，无 dash/点形冗余。
- 建议：`chartTheme.ts` 导出 `LINE_DASHES: number[][] = [[], [6,4], [2,3], [8,3,2,3]]` 常量，在 `buildChartGroups` 返回值上附带 `dash` 字段（按组索引取模），四个图表组件（SensorTrendChart / TestDataView / GasControlView / InstrumentMeasureView）接线 `borderDash: group.dash`；虚线系列 legend 符号同步（Chart.js legend 自动跟随 borderDash）。纯视觉增量，不动数据结构。
- 依据：ui-ux-pro-max `charts.csv` Trend Over Time Accessibility Notes（"solid, dashed, and dotted line styles plus direct series labels; never distinguish series by hue alone"）、Multi-Variable Comparison 同条。
- 改动量：**中小**（chartTheme + 4 个组件各一行接线 + 单测快照更新）。收益：色觉障碍可读性；打印/灰度场景系列可辨。

### 2.4 【采纳】V-D：触摸目标 40 → 44px（对应盲点 D）

- 现状：`--touch-target: 40px`，移动端按钮 min-height 全引此令牌。
- 建议：令牌值改 44px（`el-button--small` 的 36px 例外保留，`element-overrides.css:158-160`）。
- 依据：ui-ux-pro-max ux 域 Touch Target Size（iOS 44pt / Android 48dp；web 按 WCAG Target Size 规则——44 同时满足 AA 与平台惯例）。
- 改动量：**小**（一行令牌值）。收益：移动现场操作命中率；风险是移动布局局部变高，需跑移动冒烟 e2e。

### 2.5 【明确不做】

- **图表键盘可达性全量改造**（focus reveals values / +/- 缩放按钮 / 可见数据表兜底）：ui-ux-pro-max `charts.csv` 的 A11y Fallback 建议。判定不做——需要为每个图表造平行数据表与键盘交互层，改动越出"美术增量"边界进入组件结构（违反不动组件结构约束），内部工具收益不匹配成本。**登记为已知限制**。
- **全局密度加压**（ConfigProvider `size="small"` 或表格行高再压）：实证 EP 默认 `.el-table__cell` padding 已为 8px 0（`element-plus/theme-chalk/index.css`），密度本就偏高；S6 已做 25 页走查，加压回归面大、收益小。不做。
- **引入 Inter / JetBrains Mono 等 Web 字体**：ui-ux-pro-max typography 域的字体配对建议。违反零新增依赖约束；现有系统字体栈 + `tabular-nums` 已覆盖数字对齐需求。不做。
- **风格转向或参考 React/shadcn 资源重搭**：frontend-design-refs 的落地路线（shadcn blocks / Nord token / Plane 三栏）面向 React 栈，与本项目 Vue+EP 不匹配，且违反"严禁推倒重来"。该 skill 的结论（冷色 token 纪律、Grafana 式密度、Observable Plot 式克制图表）与现有 S1–S6 方向**一致**，仅作方向佐证，不产生改动。
- **dark brand 400/500 同值去重**：`dark.css:39-40` 同值是有意的档位语义（dark 下 400/500 都作 hover 亮档），改色会牵动 pulse-ring/焦点环等多处引用，收益仅为"色阶表好看"。不改值，仅在 V-A 批加注释登记。

## 3. 分批次落地建议

四批均满足：独立可验、独立可回退、零依赖零 i18n；每批收口前跑 `npm test` + `npm run test:coverage`（窄口径阈值）+ `npm run build` + 防线 grep 零输出。

| 批次 | 内容 | 优先级 | 改动量 | 验证 |
|---|---|---|---|---|
| **V7-A** | dark `::selection` 覆写（brand-200 底 + text-1 字）+ dark brand 阶梯反转注释登记 | P0 | 小 | 对比度复算 ≥4.5:1（脚本重跑）；dark 下划选目检 |
| **V7-B** | element-overrides.css light 中性色补全（bg/fill/placeholder/disabled 对称 dark）+ `#f0f4f9` 收敛 | P1 | 中 | 抽 5 页走查（日报表单、问题列表表格、弹窗、下拉、分页）；双主题截图比对；placeholder/disabled 视觉确认 |
| **V7-C** | chartTheme `LINE_DASHES` + buildChartGroups 附 dash + 四图表组件接线 | P1 | 中小 | chartTheme 既有单测快照更新后全绿；SensorTrendChart 多系列目检（含灰度打印模拟） |
| **V7-D** | `--touch-target` 40→44px | P2 | 小 | 移动冒烟 e2e（`scripts/test-e2e.sh`）复跑；底栏/按钮区目检无挤压 |

执行顺序建议：V7-A 先行（唯一 ❌，改动最小）→ V7-B（对称性收尾）→ V7-C（图表可读性）→ V7-D（移动端打磨，可与其他批并行）。若只做一批，做 V7-A。

## 4. 排除项（沿用 v4，本方案全程有效）

- 不改信息架构、路由、导航配置、组件结构、功能逻辑、API 契约。
- 不动 `--login-*` 族深渐变门面；不动 dark 侧栏深 navy 套。
- 零新增 npm 依赖、零新增 i18n key、零新增 EP 组件。
- 不引入 Web 字体、不改品牌主色 #0c7693 与十档阶梯、不改图表 8 色系色值（V7-C 只加线型冗余，不改色）。
- 不碰 `statusMeta` 注册表语义与 domain 键控结构。
- 数据库、Go 后端、py-agent 一律不碰。

## 5. 结论

S1–S6 落地质量高于预期：防线 grep 零输出、27 组对比度仅 1 组不合格、EP 双主题变量对接完整度超过官方默认。**体系已接近成熟，不建议大规模改动**；本方案的四个增量点（V7-A/B/C/D）均为证据驱动的小步补强，合计改动约 30–50 行 CSS/TS，可在一到两个工作批次内收口。其中只有 V7-A 是缺陷修复（dark 选区 1.66:1），其余三项是一致性与冗余编码的打磨。完成 V7-A～D 后，本套美术体系建议进入**维护态**：只随新功能登记令牌，不再开新美术批次。
